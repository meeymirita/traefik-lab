reverse proxy (обратный прокси) :: программа на стороне сервера, которая принимает все запросы и пересылает их нужному сервису; клиент о ней не знает
forward proxy (прямой прокси) :: прокси на стороне клиента: компьютер просит его сходить на сайт за него
upstream (бэкенд) :: сервис, на который прокси пересылает запрос
балансировщик нагрузки :: часть прокси, которая раздаёт запросы между несколькими копиями сервиса
TLS termination :: расшифровка HTTPS на входе в прокси; дальше запрос идёт по обычному HTTP внутри сети
DNS :: «телефонная книга интернета»: превращает имя в IP-адрес
SNI (Server Name Indication) :: имя сайта, которое клиент сообщает в начале TLS-рукопожатия, чтобы сервер выбрал нужный сертификат
заголовок Host :: поле HTTP-запроса с именем сайта; по нему прокси различает сайты на одном адресе и порте
entryPoint (вход) :: порт, который слушает Traefik (например, web на :80, websecure на :443)
router (роутер) :: правило «если запрос такой, отправь вот туда»; у него есть правило, вход, список middleware и сервис
service (сервис) :: куда в итоге пересылать запрос: один или несколько адресов бэкенда
middleware :: обработка запроса по пути: срезать префикс, проверить пароль, ограничить скорость и т. п.
provider (провайдер) :: источник динамической конфигурации: Docker, файлы, Kubernetes
статическая конфигурация :: настройки, которые Traefik читает при запуске (traefik.yml); после правки нужен перезапуск
динамическая конфигурация :: маршруты и middleware; меняются на лету, без перезапуска
метка (label) :: пара «ключ=значение» на контейнере, из которой Traefik строит маршрут
traefik.enable :: метка, включающая публикацию контейнера при exposedByDefault: false
exposedByDefault :: настройка провайдера Docker: публиковать ли контейнеры без явной метки traefik.enable
docker.sock :: служебный файл Docker, через который программа спрашивает демон о контейнерах; доступ к нему — риск
docker-socket-proxy :: маленький прокси, который разрешает Traefik только чтение списка контейнеров
дашборд :: веб-интерфейс Traefik: роутеры, сервисы, middleware и их ошибки
api@internal :: встроенный сервис Traefik, через который отдаются дашборд и API
@docker, @file :: суффикс имени объекта: из какого провайдера он взят
constraints :: фильтр контейнеров провайдера Docker по меткам
приоритет (priority) :: число, по которому выбирается один из нескольких подходящих роутеров; по умолчанию — длина правила
StripPrefix :: middleware, срезающий начало пути (/api/menu → /menu)
redirectScheme :: middleware или настройка входа, отправляющая клиента с http на https
CORS :: правила, разрешающие странице с одного адреса обращаться к API на другом; Traefik может отвечать на предварительный запрос OPTIONS
htpasswd :: утилита, создающая хэш пароля для basicAuth (bcrypt, ключ -B)
хэш (bcrypt) :: «отпечаток» пароля, по которому пароль не восстановить
интерполяция Compose :: подстановка $переменных в compose.yaml; поэтому знак $ в метках пишут как $$
chain :: middleware, составленный из других middleware в заданном порядке
rateLimit :: ограничение числа запросов (average за period, burst — всплеск); отказ — 429
inFlightReq :: ограничение числа одновременных запросов
ipAllowList :: пускает только адреса из перечисленных диапазонов (в v2 назывался ipWhiteList)
CIDR :: запись диапазона адресов, например 192.168.0.0/16
retry :: повтор запроса к другой копии, если не удалось соединиться; не повторяет запрос, уже дошедший до бэкенда
circuitBreaker (предохранитель) :: временно перестаёт слать запросы к больному сервису и отвечает 503 сам
forwardAuth :: проверка доступа внешним сервисом: 2xx — пускать, иначе отказ
идемпотентность :: свойство запроса: повтор не меняет результат; у POST её нет без ключа идемпотентности
Idempotency-Key :: заголовок с уникальным идентификатором операции; сервер не выполняет операцию дважды
реплика :: копия сервиса; несколько реплик Traefik балансирует по кругу
round robin :: раздача запросов копиям по очереди
healthcheck :: периодическая проверка копии; больная исключается из балансировки
sticky session :: «липкая» сессия: cookie привязывает клиента к одной копии
canary :: выкатка новой версии на малую долю трафика
blue/green :: две полные копии приложения; переключение трафика целиком весами 0/100
weighted (веса) :: сервис Traefik, делящий трафик между сервисами по весам
mirroring (зеркалирование) :: пересылка копии части запросов на второй сервис; его ответ отбрасывается
сертификат :: «паспорт» сайта с открытым ключом, подписанный удостоверяющим центром
открытый и закрытый ключ :: пара ключей; зашифрованное открытым расшифровывается только закрытым
CA (удостоверяющий центр) :: организация, чьей подписи доверяют
цепочка доверия :: путь подписей от сертификата сайта до корневого CA, известного клиенту
SAN :: список альтернативных имён в сертификате; браузер проверяет имя именно по нему
wildcard-сертификат :: сертификат на все поддомены первого уровня (*.example.com)
mkcert :: утилита для локального CA и сертификатов для разработки
TLS options :: требования к TLS-соединению: минимальная версия, шифры, sniStrict, клиентский сертификат
sniStrict :: отвергать соединения с именем, для которого нет сертификата
mTLS (взаимный TLS) :: клиент тоже предъявляет сертификат; сервер пускает только подписанные своим CA
ACME :: протокол автоматической выдачи сертификатов
Let’s Encrypt :: бесплатный публичный центр, отвечающий по ACME
staging :: учебный стенд Let’s Encrypt с мягкими лимитами; его сертификатам браузеры не доверяют
Pebble :: тестовый ACME-сервер от Let’s Encrypt; в лабе заменяет настоящий центр
challenge (вызов) :: задание ACME, доказывающее владение именем: HTTP-01, TLS-ALPN-01 или DNS-01
HTTP-01 :: проверка файлом по адресу /.well-known/acme-challenge/ на порту 80
TLS-ALPN-01 :: проверка особым сертификатом на порту 443
DNS-01 :: проверка TXT-записью в DNS; единственная выдаёт wildcard
certificatesResolver :: раздел статической конфигурации Traefik: как получать сертификаты
acme.json :: файл, где Traefik хранит ключ аккаунта и сертификаты; права только 600
HTTP/3, QUIC :: транспорт HTTP поверх UDP; сервер объявляет его заголовком Alt-Svc
TCP-роутер :: роутер для любого протокола поверх TCP; выбирает по порту и SNI
HostSNI :: правило TCP-роутера по имени в TLS-рукопожатии; HostSNI(`*`) — любое соединение
passthrough :: режим TCP-роутера: зашифрованный поток пропускается насквозь, не расшифровываясь
UDP-роутер :: роутер для протоколов поверх UDP (DNS, VPN); выбирает только по порту входа
X-Forwarded-For :: заголовок с цепочкой адресов клиента и прокси
trustedIPs :: адреса, от которых Traefik принимает заголовки X-Forwarded-* как правду
proxy protocol :: протокол, по которому балансировщик передаёт настоящий адрес клиента на уровне TCP
плагин (Yaegi) :: расширение Traefik на Go, исполняемое внутри процесса Traefik
ruleSyntax :: выбор синтаксиса правил (v2 или v3) для роутера
access log (журнал доступа) :: по строке на каждый запрос: кто, куда, какой роутер, код, время
метрика :: число, которое меняется во времени (запросы, ошибки, задержка)
Prometheus :: система, которая опрашивает метрики и хранит их во времени
Grafana :: программа для графиков и дашбордов по метрикам
RED :: три главных метрики: Rate (запросов в секунду), Errors (доля ошибок), Duration (время ответа)
перцентиль (p95) :: значение, быстрее которого отвечают 95% запросов
трассировка (tracing) :: путь одного запроса через систему со временем на каждом отрезке (спане)
OpenTelemetry (OTLP) :: стандарт отправки трасс, метрик и журналов
дымовой тест (smoke) :: быстрая проверка, что основные функции работают
